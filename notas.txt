Permitir que usuarios compren entradas SIN necesidad de crear una cuenta o iniciar sesión.

### Datos del Comprador (campos obligatorios)
| Campo | Validación |
|-------|-------------|
| Nombre | Obligatorio, mínimo 2 caracteres |
| Apellido | Obligatorio, mínimo 2 caracteres |
| Email | Obligatorio, formato válido |
| Repetir Email | Obligatorio, debe ser igual al email |
| Teléfono | Obligatorio, solo números, 8-15 dígitos |

### Plan de Implementación

#### 1. Base de Datos
```sql
ALTER TABLE entradas ADD COLUMN email_comprador TEXT;
ALTER TABLE entradas ADD COLUMN nombre_comprador TEXT;
ALTER TABLE entradas ADD COLUMN apellido_comprador TEXT;
ALTER TABLE entradas ADD COLUMN telefono_comprador TEXT;
ALTER TABLE entradas ALTER COLUMN usuario_id DROP NOT NULL;
```

#### 2. Backend - Endpoints a crear/modificar
- Nuevo endpoint: `POST /api/entradas/invitado` (sin auth)
- Nuevo endpoint: `POST /api/pagos/qr/invitado` (sin auth)
- Nuevo endpoint: `POST /api/pagos/carrito/invitado` (sin auth)
- Modificar `procesar_entrada_pagada()` para buscar email en `email_comprador` si `usuario_id` es NULL
- Modificar `validar_entrada()` para buscar datos del comprador
- Modificar `/api/entradas/buscar` para buscar en `email_comprador` también

#### 3. Frontend
- Nuevo componente "Datos del Comprador" con los 5 campos
- Modificar flujo Carrito: si no hay token, mostrar formulario de datos del comprador
- Mantener backwards compatibility con usuarios registrados

#### 4. Funcionalidades a mantener sin cambios
- Login/Registro actual
- Mis Entradas (usuarios registrados)
- Transferencia de entradas
- QR de acceso
- Validación (scanner)
- Email con ticket
- Panel admin
- Panel organizador

### Riesgos identificados
- `procesar_entrada_pagada` hace JOIN con tabla usuarios → debe buscar en `email_comprador` si `usuario_id` es NULL
- `validar_entrada` hace JOIN con tabla usuarios → debe buscar datos del comprador

### URL resultado
Los usuarios podrán comprar sin registro y luego buscar sus entradas en "Buscar Mis Entradas" ingresando su email.

## SESIÓN MIÉRCOLES 13 DE MAYO 2026

### Completado: Compra sin Registro (Invitado)

**Objetivo**: Permitir que usuarios compren entradas SIN crear cuenta ni iniciar sesión.

### Base de Datos

**Columnas agregadas a tabla `entradas`:**
```sql
ALTER TABLE entradas ADD COLUMN email_comprador TEXT;
ALTER TABLE entradas ADD COLUMN nombre_comprador TEXT;
ALTER TABLE entradas ADD COLUMN apellido_comprador TEXT;
ALTER TABLE entradas ADD COLUMN telefono_comprador TEXT;
ALTER TABLE entradas ALTER COLUMN usuario_id DROP NOT NULL;
```

**Script ejecutado**: `backend/add_columns_invitado.py`

### Backend - Funciones modificadas con LEFT JOIN

| Función | Cambio |
|---------|--------|
| `procesar_entrada_pagada()` | LEFT JOIN con usuarios. Si `usuario_id=NULL`, usa `email_comprador` |
| `validar_entrada()` | LEFT JOIN con usuarios |
| `consultar_entrada()` | LEFT JOIN con usuarios |
| `GET /api/entradas/buscar` | Busca en `usuarios.email` Y `entradas.email_comprador` |

### Backend - Endpoints nuevos (públicos - sin auth)

| Endpoint | Método | Descripción |
|----------|--------|-------------|
| `/api/entradas/invitado` | POST | Crear entrada con datos del comprador |
| `/api/pagos/qr/invitado` | POST | Generar QR de MercadoPago |
| `/api/pagos/carrito/invitado` | POST | Generar link de pago |

**Todos con rate limiting habilitado.**

### Frontend - Cambios

**1. Botón "Comprar" permite usuarios sin cuenta:**
- Ya no redirige a login
- Abre ModalCompra directamente (igual que usuarios logueados)

**2. Auto-redirect al carrito para usuarios sin cuenta:**
- Al agregar entrada al carrito, si no hay token → redirige automáticamente al carrito
- Muestra toast: "Completa los datos del comprador para continuar"

**3. Formulario "Datos del Comprador" en el carrito:**
- Campos: nombre, apellido, email, repetir email, teléfono
- Validaciones:
  - Nombre: min 2 caracteres
  - Apellido: min 2 caracteres
  - Email: formato válido
  - Repetir Email: debe ser igual al email, validacion en tiempo real, no copiar/pegar
  - Teléfono: solo números, 8-15 dígitos, no copiar/pegar

### Feature: QR MercadoPago para Invitados (Fix completo)

- Genera QR real de MP con QuickChart
- Funciona igual que usuarios registrados

**Backend**:
- `/api/pagos/qr/invitado`: Ahora llama a API de MP
- `/api/pagos/qr/{id}/status`: Retorna `email_comprador` y `total`

**Frontend**:
- Detecta `?pago=QR-xxx` en URL
- Verificación automática cada 3 segundos
- Modal "¡Compra exitosa!" con nota sobre email
- Redirige a Eventos con botón "Aceptar"
